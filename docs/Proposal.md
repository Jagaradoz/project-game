# เอกสารการค้นคว้าวิจัย

# **เอกสารการค้นคว้าวิจัย**

### **1\. Biddiss, E., & Irwin, J. (2010). Active video games to promote physical activity in children and youth: A systematic review.**

งานวิจัยนี้เป็นการทบทวนงานวิจัยเกี่ยวกับ Active Video Games (AVGs) หรือเกมที่ผู้เล่นต้องใช้การเคลื่อนไหวร่างกายในการควบคุมเกม โดยศึกษาว่าเกมประเภทนี้สามารถส่งเสริมกิจกรรมทางกายได้มากน้อยเพียงใด ผลการศึกษาพบว่า Active Video Games สามารถกระตุ้นให้ผู้เล่นเกิดการเคลื่อนไหวร่างกายและเพิ่มระดับกิจกรรมทางกายเมื่อเทียบกับการเล่นวิดีโอเกมทั่วไป งานวิจัยนี้จึงสนับสนุนแนวคิดของโครงงานที่นำการเคลื่อนไหว เช่น การก้าวซ้าย-ขวาและการวิ่งอยู่กับที่ มาใช้เป็นกลไกหลักในการควบคุมเกม

### **2\. Hamari, J., Koivisto, J., & Sarsa, H. (2014). Does gamification work? A literature review of empirical studies on gamification.**

งานวิจัยนี้เป็นการทบทวนงานศึกษาที่เกี่ยวข้องกับ Gamification หรือการนำองค์ประกอบของเกมมาใช้ในบริบทที่ไม่ใช่เกม โดยพิจารณาว่าองค์ประกอบต่าง ๆ เช่น คะแนน ความสำเร็จ ความท้าทาย และการแข่งขัน สามารถส่งผลต่อพฤติกรรมและแรงจูงใจของผู้ใช้งานได้อย่างไร

ผลจากการทบทวนงานวิจัยพบว่า Gamification สามารถส่งผลเชิงบวกต่อแรงจูงใจและการมีส่วนร่วมของผู้ใช้งานได้ในหลายบริบท อย่างไรก็ตาม ผลลัพธ์อาจแตกต่างกันไปตามรูปแบบการออกแบบและบริบทของระบบ

งานวิจัยนี้เกี่ยวข้องกับโครงงานในส่วนของ

* ระบบคะแนนและการให้รางวัล  
* ระดับความยากและความท้าทาย  
* ความก้าวหน้าของผู้เล่นผ่าน Stage และ Biome  
* การใช้กลไกเกมเพื่อเพิ่มแรงจูงใจในการออกกำลังกาย

จึงเป็นพื้นฐานในการออกแบบองค์ประกอบ Gamification ภายในเกม เพื่อศึกษาว่าองค์ประกอบเหล่านี้ช่วยเพิ่มแรงจูงใจในการเคลื่อนไหวของผู้เล่นได้หรือไม่

### **3\. Lee, J., Ahn, S. C., & Hwang, J. I. (2018). A walking-in-place method for virtual reality using position and orientation tracking.**

งานวิจัยนี้นำเสนอวิธีการจำลองการเดินในสถานที่เดิม โดยตรวจจับการเคลื่อนไหวของผู้ใช้งานและนำข้อมูลที่ได้มาใช้ควบคุมการเคลื่อนที่ในสภาพแวดล้อมเสมือน แนวคิดดังกล่าวช่วยให้ผู้ใช้งานสามารถสร้างการเคลื่อนที่ในเกมหรือสภาพแวดล้อมเสมือนได้โดยไม่จำเป็นต้องเดินจริงเป็นระยะทางไกล

แนวคิดจากงานวิจัยนี้มีความเกี่ยวข้องกับโครงงานในด้านการนำ การเคลื่อนไหวของร่างกายมาแปลงเป็นคำสั่งควบคุมภายในเกม โดยเฉพาะการตรวจจับการเคลื่อนไหวของผู้เล่นเพื่อใช้เป็น Input แทนการใช้ Keyboard หรือ Controller

สำหรับโครงงานนี้สามารถนำแนวคิดดังกล่าวมาประยุกต์ใช้กับ

* การตรวจจับการวิ่งอยู่กับที่  
* การนำการเคลื่อนไหวของร่างกายมาใช้ควบคุมตัวละคร  
* การสร้างเกมที่ผู้เล่นสามารถควบคุมตัวละครด้วยร่างกายของตนเอง

งานวิจัยนี้ศึกษาการ วิ่งอยู่กับที่ และเปรียบเทียบกับการทดสอบสมรรถภาพทางกายรูปแบบอื่น โดยแสดงให้เห็นว่าการวิ่งอยู่กับที่สามารถทำให้เกิดการออกแรงทางกายและเพิ่มความต้องการทางสรีรวิทยาของร่างกายได้

# บทคัดย่อ

โครงงานนี้มีวัตถุประสงค์ในการนำเสนอเว็บไซต์เกมออกกำลังกายที่ใช้เทคโนโลยีตรวจจับท่าทางร่างกาย (Pose Estimation) ผ่านกล้องเว็บแคม เพื่อให้การเคลื่อนไหวร่างกายของผู้เล่นเป็นกลไกควบคุมเกมโดยตรง ผู้เล่นสามารถขยับร่างกายไปทางซ้ายหรือขวาเพื่อควบคุมตัวละครในการหลบหลีก และวิ่งอยู่กับที่เพื่อให้ตัวละครยิงโจมตีศัตรูอย่างต่อเนื่อง หากผู้เล่นหยุดเคลื่อนไหว ระบบจะหยุดการโจมตี เพื่อส่งเสริมให้ผู้เล่นมีการเคลื่อนไหวร่างกายอย่างต่อเนื่อง นอกจากนี้ ระบบยังประกอบด้วยองค์ประกอบของเกม เช่น ระบบศัตรู ระบบคะแนน ระดับความยากที่ปรับเปลี่ยนได้ และแถบพลังชีวิตของศัตรูหรือบอส เพื่อเพิ่มความน่าสนใจและแรงจูงใจในการออกกำลังกาย โดยระบบตรวจจับท่าทางจะประมวลผลบนฝั่งเบราว์เซอร์ของผู้ใช้แบบเรียลไทม์ โดยไม่ส่งภาพจากกล้องขึ้นไปยังเซิร์ฟเวอร์

# Abstract

This project presents a webcam-based exercise game website that utilizes pose estimation technology to enable players' body movements to directly control the game. Players can move their bodies to the left or right to control the character for avoiding obstacles and enemies, while jogging in place allows the character to continuously attack enemies. When the player stops moving, the character stops attacking, encouraging continuous physical movement throughout gameplay. The system also incorporates game elements, including an enemy system, scoring system, adjustable difficulty levels, and enemy or boss health bars, to enhance engagement and motivation for physical activity. The pose detection system operates in real time on the user's browser without transmitting webcam video to the server.

Keywords: Exercise game, Exergame, Pose estimation, Webcam, Gamification, Physical activity

# 1\. บทนำ

## 1.1 ที่มาและความสำคัญของปัญหา

ปัจจุบันประชาชนชาวไทยจำนวนมากมีพฤติกรรมเนือยนิ่งและมีกิจกรรมทางกายไม่เพียงพอ ซึ่งเป็นปัจจัยเสี่ยงสำคัญต่อโรคไม่ติดต่อเรื้อรัง โดยการศึกษาของ Topothai et al. (2020) พบว่าระดับกิจกรรมทางกายของประชาชนชาวไทยยังต่ำกว่าระดับที่แนะนำเพื่อสุขภาพที่ดี สะท้อนให้เห็นถึงความจำเป็นในการพัฒนาแนวทางหรือเครื่องมือที่สามารถกระตุ้นให้ประชาชนเคลื่อนไหวร่างกายได้อย่างต่อเนื่อง งานวิจัยด้าน Active Video Games (AVGs) พบว่าการใช้การเคลื่อนไหวร่างกายเป็นกลไกควบคุมเกมสามารถเพิ่มอัตราการเต้นของหัวใจ การใช้ออกซิเจน และการเผาผลาญพลังงานได้ในระดับใกล้เคียงกับการออกกำลังกายรูปแบบทั่วไป (Peng, Lin, & Crouse, 2011\) นอกจากนี้ งานวิจัยด้าน Gamification ยังชี้ให้เห็นว่าองค์ประกอบของเกมสามารถช่วยเพิ่มแรงจูงใจและการมีส่วนร่วมของผู้ใช้ โดยเฉพาะในบริบทด้านสุขภาพ (Hamari et al., 2014; Johnson et al., 2016\)

โครงงานนี้จึงพัฒนาเว็บไซต์เกมออกกำลังกายที่ใช้การตรวจจับท่าทางร่างกาย (Pose Estimation) ผ่านกล้องเว็บแคม โดยให้ผู้เล่นขยับตัวไปทางซ้ายหรือขวาเพื่อควบคุมตัวละคร และวิ่งอยู่กับที่เพื่อให้ตัวละครยิงโจมตีศัตรู หากผู้เล่นหยุดเคลื่อนไหว ตัวละครจะหยุดยิงทันที เพื่อส่งเสริมให้เกิดการเคลื่อนไหวอย่างต่อเนื่อง โดยระบบตรวจจับท่าทางสามารถประมวลผลแบบเรียลไทม์บนคอมพิวเตอร์ทั่วไปโดยไม่ต้องใช้อุปกรณ์เฉพาะทาง โครงงานนี้มุ่งศึกษาว่าการออกแบบ Exergame ที่ใช้การเคลื่อนไหวร่างกายเป็นกลไกควบคุมโดยตรง ร่วมกับองค์ประกอบของเกม จะสามารถส่งเสริมกิจกรรมทางกายและแรงจูงใจภายในของผู้ใช้งานได้มากกว่าการเคลื่อนไหวรูปแบบเดียวกันที่ไม่มีองค์ประกอบของเกมหรือไม่

## 1.2 คำถามการวิจัย

•     องค์ประกอบของเกม ได้แก่ ระบบศัตรู ระบบคะแนน และระดับความยากที่ปรับเปลี่ยนได้ ส่งผลต่อแรงจูงใจภายในของผู้เล่นอย่างไร 

•     กลไกเกม เช่น ระบบศัตรู ระบบคะแนน และระดับความยากที่ปรับเปลี่ยนได้ ส่งผลต่อแรงจูงใจภายใน (Intrinsic Motivation) และความต่อเนื่องในการเล่น/ออกกำลังกายของผู้ใช้งานอย่างไร

# 2\. วัตถุประสงค์ของโครงงาน

•     เพื่อพัฒนาเว็บไซต์เกมออกกำลังกาย (Exergame) ที่ใช้เทคโนโลยีตรวจจับท่าทางร่างกายผ่านกล้องเว็บแคม โดยให้การเคลื่อนไหวร่างกายของผู้เล่น (การก้าวซ้าย-ขวาเพื่อหลบ และการวิ่งอยู่กับที่เพื่อยิง) เป็นกลไกควบคุมเกมโดยตรง

•     เพื่อศึกษาผลของกลไกเกม เช่น ระบบศัตรู ระบบคะแนน และระดับความยาก ต่อความเข้มข้นของกิจกรรมทางกายและแรงจูงใจภายในของผู้เล่น

•     เพื่อประเมินความแม่นยำและความหน่วง (Latency) ของระบบตรวจจับการเคลื่อนไหวผ่านกล้องเว็บแคม ว่าเพียงพอต่อการใช้เป็นกลไกควบคุมเกมแบบเรียลไทม์หรือไม่

# 3\. ขอบเขตของโครงงาน

## 3.1 กลุ่มเป้าหมาย

ประชาชนทั่วไปที่มีอุปกรณ์คอมพิวเตอร์, แล็ปท็อปหรือโทรศัพท์มือถือที่มีกล้องเว็บแคมและเชื่อมต่ออินเทอร์เน็ตได้ โดยเฉพาะกลุ่มนักศึกษาในมหาวิทยาลัย หรือ พนักงานออฟฟิศวัยทำงาน ที่มีพื้นที่ว่างเพียงพอสำหรับการขยับตัวหน้าจอ (โดยประมาณ 1.5–2 เมตร)

## 3.2 ฟังก์ชันของเว็บไซต์

•     ระบบตรวจจับท่าทางร่างกายแบบเรียลไทม์ผ่านกล้องเว็บแคม (Real-time Pose Estimation) โดยประมวลผลบนฝั่งเบราว์เซอร์ของผู้ใช้ (Client-side) เพื่อลดความหน่วงและรักษาความเป็นส่วนตัวของภาพผู้ใช้ โดยไม่ต้องส่งวิดีโอขึ้นเซิร์ฟเวอร์

•     กลไกควบคุมตัวละครด้วยร่างกาย: การก้าว/เอียงตัวไปทางซ้าย ให้ตัวละครเคลื่อนที่และโจมตีศัตรูทางด้านซ้าย และการก้าว/เอียงตัวไปทางขวา ให้ตัวละครเคลื่อนที่และโจมตีศัตรูทางด้านขวา 

•     กลไก "วิ่งอยู่กับที่เพื่อยิง" (Jog-to-Shoot): ระบบตรวจจับจังหวะการยกเข่า/สะโพกขึ้น-ลงสลับกันอย่างต่อเนื่องคล้ายการวิ่งจ็อกกิ้งอยู่กับที่ เพื่อกระตุ้นให้ตัวละครยิงอัตโนมัติ หากผู้เล่นหยุดนิ่ง ปืนจะหยุดยิงทันที เพื่อบังคับให้ผู้เล่นเคลื่อนไหวร่างกายอย่างต่อเนื่องตลอดการเล่น

•     ระบบศัตรูที่วิ่งเข้าหาตัวละครของผู้เล่น พร้อมระดับความยากที่เพิ่มขึ้นตามเวลาหรือคะแนน (Difficulty Progression) และสามารถปรับระดับความยากเริ่มต้นได้ตามความสามารถของผู้เล่นแต่ละคน

•     แถบพลังชีวิตศัตรู/บอส (Enemy Health Bar) แสดงที่กึ่งกลางด้านบนของหน้าจอ ลดลงตามความเสียหายที่ผู้เล่นสร้างได้แบบเรียลไทม์ เพื่อให้ผู้เล่นเห็นความคืบหน้าของการต่อสู้อย่างชัดเจน

•     ระบบคะแนนและหน้าสรุปผลหลังจบเกม แสดงคะแนน จำนวนศัตรูที่กำจัดได้ ระยะเวลาการเล่น และปริมาณการเคลื่อนไหวหรือก้าวเดินที่นับได้ระหว่างการเล่นเกม

•     หน้าโปรไฟล์ผู้ใช้ แสดงประวัติการเล่น สถิติสะสม และตารางคะแนนสูงสุด (Leaderboard)

## 3.3 แพลตฟอร์มที่รองรับ

พัฒนาในรูปแบบเว็บไซต์ (Web Application) ที่เข้าถึงได้ผ่านเว็บเบราว์เซอร์บนคอมพิวเตอร์หรือแล็ปท็อปที่มีกล้องเว็บแคม

## 3.4 ขอบเขตการประเมินผล

•     ประเมินระดับแรงจูงใจและความพึงพอใจในการใช้งาน โดยใช้แบบสอบถามที่ประยุกต์จากทฤษฎีแรงจูงใจ (Intrinsic Motivation Inventory: IMI) แจกจ่ายให้กับกลุ่มผู้ทดลองใช้งานหลังสิ้นสุดระยะเวลาโครงการ

•     ประเมินความแม่นยำเชิงเทคนิคของระบบตรวจจับท่าทาง เช่น อัตราการตรวจจับท่าทางผิดพลาดและความหน่วงของระบบในสภาพแวดล้อมการเล่นจริง

# 4\. แนวคิด ทฤษฎี และงานวิจัยที่เกี่ยวข้อง

## 4.1 ประสิทธิภาพของ Exergame ต่อกิจกรรมทางกาย

งานวิเคราะห์อภิมานของ Peng, Lin, & Crouse (2011) ที่ทบทวนงานวิจัยเกี่ยวกับเกมที่ต้องใช้การเคลื่อนไหวร่างกาย (Active Video Games: AVGs) พบว่าการเล่น AVGs ส่งผลให้อัตราการเต้นของหัวใจ การใช้ออกซิเจน และการเผาผลาญพลังงานเพิ่มขึ้นอย่างมีนัยสำคัญเมื่อเทียบกับภาวะพัก และมีขนาดผลใกล้เคียงกับการออกกำลังกายรูปแบบทั่วไป ผลการศึกษานี้สนับสนุนแนวทางการออกแบบของโครงงานนี้ที่ให้การเคลื่อนไหวร่างกายเป็นกลไกควบคุมเกมโดยตรง แทนที่จะเป็นเพียงชั้นให้รางวัลเหนือกิจกรรมที่บันทึกแบบพาสซีฟ

## 

## 4.2 เทคโนโลยีตรวจจับท่าทางร่างกายด้วยกล้อง (Camera-based Pose Estimation)

Exergame ที่ใช้การตรวจจับการเคลื่อนไหวแบบไร้อุปกรณ์สวมใส่ (Markerless Motion Capture) ในอดีตมักอาศัยฮาร์ดแวร์เฉพาะทาง เช่น กล้อง Kinect ซึ่ง Nathan, Huynh, Rubenson, & Rosenberg (2015) ได้แสดงให้เห็นว่าข้อมูลการเคลื่อนไหวจาก Kinect สามารถนำมาประมาณค่าการเผาผลาญพลังงานระหว่างเล่นเกมได้ อย่างไรก็ตาม เทคโนโลยีตรวจจับท่าทางบนเว็บเบราว์เซอร์ในปัจจุบัน เช่น BlazePose ซึ่งเป็นโครงข่ายประสาทเทียมขนาดเล็กที่ออกแบบมาสำหรับการประมวลผลแบบเรียลไทม์บนอุปกรณ์ทั่วไป สามารถตรวจจับตำแหน่งข้อต่อร่างกาย 33 จุดได้ที่อัตรามากกว่า 30 เฟรมต่อวินาที โดยไม่ต้องใช้ฮาร์ดแวร์พิเศษ (Bazarevsky et al., 2020\) ทำให้การพัฒนา Exergame ในรูปแบบเว็บไซต์ที่เข้าถึงได้ด้วยกล้องเว็บแคมทั่วไปมีความเป็นไปได้ทางเทคนิคมากขึ้น ซึ่งเป็นแนวทางเทคโนโลยีหลักที่โครงงานนี้เลือกใช้

## 4.3 ประสิทธิภาพของ Gamification

Hamari et al. (2014) ได้สรุปว่า Gamification สามารถส่งผลเชิงบวกต่อพฤติกรรมผู้ใช้ในหลายกรณี โดยเฉพาะในด้านการมีส่วนร่วมและแรงจูงใจ และนำเสนอกรอบการจัดหมวดหมู่องค์ประกอบของเกม (Game Design Elements) ซึ่งถูกนำไปใช้ต่อในงานวิจัยด้านสุขภาพอย่างแพร่หลาย

## 4.4 ผลกระทบด้านพฤติกรรมและแรงจูงใจ

Alsawaier (2018) พบว่าองค์ประกอบเกม เช่น คะแนน ระดับ และรางวัล สามารถช่วยกระตุ้นให้ผู้ใช้มีความต้องการพัฒนาและแข่งขันกับตนเองมากขึ้น นอกจากนี้ Johnson et al. (2016) ยังชี้ให้เห็นว่า Gamification สามารถนำไปใช้ในด้านสุขภาพเพื่อส่งเสริมพฤติกรรมเชิงบวก เช่น การออกกำลังกาย และระบุถึงช่องว่างทางวิชาการว่ายังไม่มีการวัดผลของกลไกเกมต่อแรงจูงใจภายในโดยตรงมากนัก ซึ่งเป็นประเด็นที่โครงงานนี้มุ่งศึกษาเพิ่มเติม King, Greaves, Exeter, & Darzi (2013) ได้เสนอแนวคิดการผสานหลักการออกแบบเกม (Game Mechanics) เข้ากับทฤษฎีด้านสาธารณสุขและพฤติกรรมศาสตร์ เพื่อพัฒนา "เกมที่มีจุดมุ่งหมาย" (Games with Purpose) สำหรับปรับเปลี่ยนพฤติกรรมสุขภาพผ่านแพลตฟอร์มเกมบนอุปกรณ์อิเล็กทรอนิกส์

## 4.5 ปัญหาด้านสุขภาพของคนไทย

ในบริบทของประเทศไทย งานวิจัยของ Topothai et al. (2020) พบว่าคนไทยมีจำนวนก้าวเดินเฉลี่ยต่อวันต่ำกว่ามาตรฐานที่แนะนำ ซึ่งสะท้อนถึงปัญหาพฤติกรรมเนือยนิ่ง ขณะที่ Phababpha et al. (2024) พบว่าการเพิ่มจำนวนก้าวเดินมีความสัมพันธ์กับสุขภาพหลอดเลือดที่ดีขึ้น ดังนั้น การนำแนวคิด Exergame และ Gamification มาประยุกต์ใช้ในเว็บไซต์ส่งเสริมการเคลื่อนไหว จึงมีศักยภาพในการช่วยแก้ไขปัญหาการขาดกิจกรรมทางกาย และส่งเสริมสุขภาพในระยะยาว

## 4.6 กรอบทฤษฎีแรงจูงใจ: Self-Determination Theory (SDT)

โครงงานนี้ใช้ Self-Determination Theory เป็นกรอบแนวคิดหลักในการออกแบบกลไกเกม โดยเน้น 3 องค์ประกอบสำคัญ ได้แก่ ความรู้สึกมีอิสระในการเลือก (Autonomy) ความรู้สึกว่าตนเองมีความสามารถและพัฒนาขึ้น (Competence) และความรู้สึกเชื่อมโยงกับผู้อื่น (Relatedness) โดยใช้แบบสอบถาม Intrinsic Motivation Inventory (IMI) ซึ่งพัฒนาบนพื้นฐานของ SDT เป็นเครื่องมือวัดผลแรงจูงใจของผู้ใช้งาน

# 5\. แนวทางการออกแบบระบบ

โครงงานนี้เลือกแนวทางการออกแบบเป็น Exergame โดยให้การเคลื่อนไหวร่างกายของผู้เล่นเป็นอินพุตควบคุมตัวละครและเหตุการณ์ในเกมโดยตรง (Movement-as-Direct-Input) กล่าวคือ ผู้เล่นต้องขยับร่างกายจริงเพื่อควบคุมตัวละครในการเคลื่อนที่และโจมตีศัตรู โดยไม่มีการควบคุมด้วยคีย์บอร์ดหรือเมาส์ ซึ่งแตกต่างจากแนวทาง "Fitness-first with Gamification Layer" ที่ให้กลไกเกมเป็นเพียงชั้นเสริมแรงจูงใจเหนือการออกกำลังกายที่บันทึกข้อมูลแบบพาสซีฟ (เช่น การนับก้าวเดินจากเซนเซอร์) แนวทาง Exergame ที่โครงงานนี้เลือกใช้สอดคล้องกับหลักฐานเชิงประจักษ์ในบทที่ 4 ที่แสดงให้เห็นว่า Exergame สามารถกระตุ้นความเข้มข้นของกิจกรรมทางกายได้ใกล้เคียงกับการออกกำลังกายทั่วไป (Peng, Lin, & Crouse, 2011\) และเทคโนโลยีตรวจจับท่าทางบนเบราว์เซอร์ในปัจจุบันก็รองรับการพัฒนาแนวทางนี้ได้โดยไม่ต้องใช้ฮาร์ดแวร์พิเศษ (Bazarevsky et al., 2020\)

นอกจากนี้ ระบบเกมถูกออกแบบให้มีโครงสร้าง Biome และ Stage เพื่อสร้างความหลากหลายและความรู้สึกก้าวหน้าในการเล่น โดยแต่ละ Biome จะมีจำนวน 10 Stages ซึ่งแต่ละ Stage จะเป็นด่านที่ผู้เล่นต้องเล่นและเอาชนะศัตรูตามเงื่อนไขที่กำหนด เมื่อผ่านครบ 10 Stages จะสามารถปลดล็อก Biome ถัดไป เช่น Forest Biome และ Desert Biome โดยแต่ละ Biome สามารถมีรูปแบบฉาก ศัตรู และระดับความยากที่แตกต่างกัน เพื่อสร้างความหลากหลายและความท้าทายในการเล่นอย่างต่อเนื่อง

## 5.1 หลักการออกแบบฟีเจอร์ที่สำคัญ

* ระบบปรับเทียบก่อนเริ่มเกม (Calibration) เพื่อตรวจสอบตำแหน่งกล้อง แสงสว่าง และพื้นที่ว่างที่เพียงพอสำหรับการขยับตัวของผู้เล่น ก่อนเข้าสู่หน้าเกม เพื่อความปลอดภัยและความแม่นยำของระบบตรวจจับ  
* ระบบด่านและพื้นที่ (Biome & Stage System) โดยแบ่งเกมออกเป็นหลาย Biome เช่น Forest Biome และ Desert Biome และกำหนดให้แต่ละ Biome ประกอบด้วย 10 Stages ผู้เล่นต้องผ่านแต่ละ Stage ตามลำดับเพื่อปลดล็อก Stage และ Biome ถัดไป โดยระดับความยากและรูปแบบของศัตรูสามารถเพิ่มขึ้นตามความก้าวหน้าของผู้เล่น  
* ระบบไม่ลงโทษรุนแรงเมื่อพลาด (Non-punitive Design) มีระบบพลังชีวิตหรือโอกาสเริ่มใหม่ที่เหมาะสม เพื่อลดความรู้สึกกดดัน (Pressure/Tension)  
* ผลป้อนกลับทันที (Immediate Feedback) ทั้งภาพและเสียง เมื่อผู้เล่นโจมตีโดนศัตรู เพื่อเสริมความรู้สึกว่าตนเองมีความสามารถ (Competence)  
* แสดงแถบพลังชีวิตของศัตรู/บอสอย่างชัดเจนที่กึ่งกลางด้านบนของจอ (Visible Progress Feedback) เพื่อให้ผู้เล่นเห็นผลลัพธ์จากความพยายามของตนเองอย่างต่อเนื่องตลอดการเล่น เสริมความรู้สึกว่าตนเองมีความสามารถ (Competence) ตามแนวคิด SDT  
* ระบบความก้าวหน้าของผู้เล่น (Progression System) แสดง Stage ที่ผ่านแล้ว Stage ปัจจุบัน และ Stage ที่ยังไม่ปลดล็อก รวมถึงความคืบหน้าของแต่ละ Biome เพื่อให้ผู้เล่นเห็นเป้าหมายและความก้าวหน้าของตนเองอย่างชัดเจน  
* ไม่ใช้ระบบสกุลเงินจริงหรือการซื้อขายภายในเว็บไซต์ (In-app Purchase) เพื่อลดความเสี่ยงของปรากฏการณ์ Overjustification Effect ซึ่งอาจบั่นทอนแรงจูงใจภายในของผู้ใช้งาน

## 5.2 การอ้างอิงด้านสไตล์ภาพ (Visual Style Reference)

ด้าน UI และสไตล์ภาพของเกม โครงงานนี้อ้างอิงแนวทางจากเกมมือถือแนว Hyper-casual Crowd Runner ที่มีฉากต่อสู้กับศัตรู/บอสตัวใหญ่ (Boss Battle) ซึ่งมีลักษณะเด่นคือ HUD ที่เรียบง่ายแต่ให้ข้อมูลชัดเจน โดยเฉพาะแถบพลังชีวิตของบอสที่วางกึ่งกลางด้านบนของจอ ตัวเลขคะแนน/ความเสียหายที่มองเห็นง่าย และภาพเอฟเฟกต์แสง (เช่น ลำแสงหรือกระสุน) ที่ช่วยให้ผู้เล่นรับรู้ผลของการกระทำได้ทันที

สำหรับโครงสร้างฉาก โครงงานจะใช้แนวคิด Biome เพื่อแบ่งบรรยากาศของเกมออกเป็นพื้นที่ที่แตกต่างกัน เช่น Forest Biome และ Desert Biome โดยแต่ละ Biome จะมี 10 Stages เพื่อสร้างความรู้สึกของการเดินทางและความก้าวหน้าในเกม ทั้งนี้ โครงงานจะออกแบบงานศิลป์ (Art Asset) ของตนเองขึ้นใหม่ทั้งหมด โดยนำมาเฉพาะแนวคิดด้านโครงสร้าง HUD การจัดลำดับด่าน และจังหวะผลป้อนกลับเชิงภาพมาปรับใช้เท่านั้น ไม่ใช้สินทรัพย์ภาพหรือตัวละครจากเกมต้นฉบับใดๆ

# 7\. สถาปัตยกรรมของระบบ (System Architecture)

ระบบถูกออกแบบในรูปแบบ Client-Server Architecture โดยให้การประมวลผลภาพและการตรวจจับท่าทางร่างกายทำงานทั้งหมดบนฝั่งเบราว์เซอร์ของผู้ใช้ (Client-side Inference) ซึ่งหมายความว่าวิดีโอจากกล้องเว็บแคมของผู้เล่นจะไม่ถูกส่งขึ้นไปยังเซิร์ฟเวอร์ มีเพียงข้อมูลผลลัพธ์ของเกม (คะแนน สถิติการเคลื่อนไหว) เท่านั้นที่จะถูกส่งไปจัดเก็บที่ฝั่งเซิร์ฟเวอร์ ซึ่งช่วยลดความหน่วงของระบบควบคุมเกมและรักษาความเป็นส่วนตัวของผู้ใช้งาน โดยแบ่งโครงสร้างของระบบออกเป็น 4 ส่วนหลัก ดังนี้

| ส่วนประกอบ | หน้าที่หลัก | เทคโนโลยีที่ใช้ |
| ----- | ----- | ----- |
| ส่วนติดต่อผู้ใช้/เกม (Frontend) | แสดงผลฉากเกม ตัวละคร ศัตรู คะแนน และรับภาพจากกล้องเว็บแคมผ่าน getUserMedia API | React / Next.js, HTML5 Canvas หรือ Phaser.js (2D Game Engine) |
| ส่วนตรวจจับท่าทาง (Pose Detection) | ประมวลผลภาพจากกล้องแบบเรียลไทม์บนฝั่งไคลเอนต์ เพื่อตรวจจับตำแหน่งข้อต่อร่างกาย และแปลงเป็นสัญญาณควบคุมเกม (ก้าวซ้าย/ขวา, จังหวะวิ่งอยู่กับที่) | MediaPipe / TensorFlow.js (BlazePose หรือ MoveNet) ทำงานผ่าน WebAssembly/WebGL บนเบราว์เซอร์ |
| ส่วนประมวลผล (Backend / Server) | จัดการบัญชีผู้ใช้ บันทึกผลการเล่น คะแนน และสถิติกิจกรรมทางกาย พร้อมให้บริการ API สำหรับหน้าโปรไฟล์และ Leaderboard | Node.js, Express.js |
| ฐานข้อมูล (Database) | จัดเก็บข้อมูลผู้ใช้ ประวัติการเล่น และสถิติสะสม | Firebase / MySQL |

 

# 8\. โครงสร้างหน้าจอหลักของเว็บไซต์

•     หน้าแรก (Home / Landing): แนะนำเกมและวิธีการเล่น พร้อมปุ่มเริ่มเล่น

•     หน้าปรับเทียบกล้อง (Calibration): ตรวจสอบกล้อง แสงสว่าง และพื้นที่ว่าง พร้อมทดสอบการตรวจจับท่าทางก่อนเข้าสู่เกมจริง

•     หน้าเกม (Gameplay): แสดงตัวละคร ศัตรู/บอสพร้อมแถบพลังชีวิต (Health Bar) ที่กึ่งกลางด้านบนของจอ คะแนน และภาพขนาดเล็กจากกล้องพร้อมโครงร่างจุดตรวจจับ (Skeleton Overlay) ที่มุมจอ เพื่อให้ผู้เล่นตรวจสอบท่าทางของตนเองระหว่างเล่น ออกแบบในสไตล์ภาพสีสันสดใสแบบเกมแนว Hyper-casual Crowd Runner เพื่อสร้างความตื่นเต้นและดึงดูดผู้เล่น

•     หน้าสรุปผลหลังเล่น (Result Summary): แสดงคะแนน ระยะเวลาเล่น และปริมาณการเคลื่อนไหว/พลังงานที่ใช้โดยประมาณ

•     หน้าโปรไฟล์ (Profile): แสดงประวัติการเล่น สถิติสะสม และตารางคะแนนสูงสุด (Leaderboard)

# 9\. วิธีการประเมินผล

## 9.1 เครื่องมือวัดแรงจูงใจ: Intrinsic Motivation Inventory (IMI)

ใช้แบบสอบถาม IMI ซึ่งพัฒนาบนพื้นฐานของ Self-Determination Theory โดยคัดเลือกเฉพาะองค์ประกอบย่อย (Subscale) ที่เกี่ยวข้องกับฟีเจอร์ของระบบโดยตรง ได้แก่ ความสนใจ/ความเพลิดเพลิน (Interest/Enjoyment) การรับรู้ความสามารถของตนเอง (Perceived Competence) ความพยายามและความสำคัญ (Effort/Importance) ความรู้สึกกดดัน (Pressure/Tension) และการรับรู้ถึงคุณค่าและประโยชน์ (Value/Usefulness)

## 9.2 ขั้นตอนการเตรียมเครื่องมือ

•     แปลแบบสอบถาม IMI จากภาษาอังกฤษเป็นภาษาไทย

•     แปลกลับเป็นภาษาอังกฤษ (Back-translation) โดยผู้แปลอีกคนหนึ่งที่ไม่เห็นต้นฉบับ เพื่อตรวจสอบความถูกต้องของความหมาย

•     ทดสอบนำร่อง (Pilot Test) กับกลุ่มตัวอย่างขนาดเล็ก และตรวจสอบค่าความเชื่อมั่น (Cronbach's Alpha)

## 9.3 รูปแบบการทดลอง

แบ่งกลุ่มผู้เข้าร่วมทดลองออกเป็น 2 กลุ่ม ได้แก่ กลุ่มทดลองที่เล่นเว็บไซต์เกมออกกำลังกายฉบับสมบูรณ์ (มีตัวละคร ระบบศัตรู คะแนน และความยากที่ปรับเปลี่ยนได้) และกลุ่มควบคุมที่ทำกิจกรรมการเคลื่อนไหวรูปแบบเดียวกัน (ก้าวซ้าย-ขวาและวิ่งอยู่กับที่) ผ่านระบบตรวจจับท่าทางชุดเดียวกัน แต่ไม่มีองค์ประกอบของเกม (ไม่มีตัวละคร ศัตรู หรือคะแนน) เป็นเพียงการนับจำนวนครั้งของการเคลื่อนไหว จากนั้นวัดผลคะแนน IMI ของทั้งสองกลุ่มภายหลังการใช้งานครบระยะเวลาที่กำหนด และวิเคราะห์เปรียบเทียบด้วยสถิติ Independent t-test เพื่อประเมินว่ากลไก Exergame ส่งผลต่อแรงจูงใจภายในของผู้ใช้งานอย่างมีนัยสำคัญหรือไม่ นอกจากนี้ จะนำข้อมูลปริมาณการเคลื่อนไหวที่บันทึกโดยระบบของทั้งสองกลุ่มมาวิเคราะห์เปรียบเทียบ เพื่อประเมินว่าองค์ประกอบของเกมส่งผลต่อความเข้มข้นและความต่อเนื่องของกิจกรรมทางกายอย่างมีนัยสำคัญหรือไม่

# 10\. ประโยชน์ที่คาดว่าจะได้รับ

•     ได้ต้นแบบเว็บไซต์เกมออกกำลังกายที่ใช้กล้องเว็บแคมเป็นตัวควบคุม ซึ่งเข้าถึงได้ง่ายโดยไม่ต้องใช้อุปกรณ์เสริมพิเศษ

•     ได้องค์ความรู้เชิงประจักษ์เกี่ยวกับผลของการออกแบบ Exergame แบบ Movement-as-Direct-Input ต่อความเข้มข้นของกิจกรรมทางกายและแรงจูงใจภายในของผู้ใช้งานในบริบทของประเทศไทย

•     เป็นแนวทางอ้างอิงสำหรับการพัฒนา Exergame บนเว็บเบราว์เซอร์โดยใช้เทคโนโลยีตรวจจับท่าทางแบบ Client-side ซึ่งยังมีการศึกษาจำกัดในบริบทของงานโครงงานนักศึกษาไทย

11\. แผนการดำเนินงาน (Project Plan)

## 11.1 ศึกษางานวิจัยและเทคโนโลยีที่เกี่ยวข้อง

ในขั้นตอนเริ่มต้นของโครงการ ทำการค้นคว้าและศึกษาเอกสารวิชาการ งานวิจัย และเทคโนโลยีที่เกี่ยวข้องกับ Exergame, Gamification, การตรวจจับท่าทางร่างกาย (Pose Estimation) และการพัฒนาเกมบนเว็บ เพื่อใช้เป็นแนวทางในการออกแบบระบบและกำหนดรูปแบบการเล่นให้เหมาะสมกับวัตถุประสงค์ของโครงงาน

## 11.2 วิเคราะห์และออกแบบระบบ

กำหนดโครงสร้างและรูปแบบการทำงานของเว็บไซต์ โดยออกแบบสถาปัตยกรรมระบบ การทำงานของระบบตรวจจับท่าทาง และการเชื่อมต่อระหว่างส่วน Frontend, Pose Detection, Backend และ Database รวมถึงกำหนดรูปแบบการควบคุมตัวละครด้วยการเคลื่อนไหวของผู้เล่น

## 11.3 ออกแบบ UI/UX และโครงสร้างเกม

ออกแบบส่วนติดต่อผู้ใช้และประสบการณ์การใช้งานของเกม เช่น หน้าแรก หน้าปรับเทียบกล้อง หน้า Gameplay หน้าสรุปผล และหน้า Profile รวมถึงออกแบบโครงสร้าง Biome และ Stage โดยกำหนดให้แต่ละ Biome ประกอบด้วย 10 Stages และออกแบบรูปแบบศัตรู ระดับความยาก และองค์ประกอบต่าง ๆ ภายในเกม

## 11.4 พัฒนาระบบตรวจจับท่าทางร่างกาย

พัฒนาโมดูล Pose Detection สำหรับตรวจจับการเคลื่อนไหวของผู้เล่นผ่านกล้องเว็บแคมแบบเรียลไทม์ โดยนำข้อมูลตำแหน่งข้อต่อร่างกายมาแปลงเป็นสัญญาณควบคุมเกม เช่น การก้าวหรือเอียงตัวไปทางซ้ายและขวาเพื่อควบคุมทิศทางการโจมตี และการวิ่งอยู่กับที่เพื่อกระตุ้นการโจมตี

## 11.5 พัฒนากลไกเกมและระบบ Biome/Stage

พัฒนากลไกหลักของเกม ได้แก่ ตัวละคร ระบบโจมตี ระบบศัตรู ระบบพลังชีวิต ระบบคะแนน และระบบปรับระดับความยาก รวมถึงพัฒนาระบบ Biome และ Stage โดยแต่ละ Biome มี 10 Stages และกำหนดการเพิ่มระดับความยากตามความก้าวหน้าของผู้เล่น

## 11.6 พัฒนาระบบ Backend และฐานข้อมูล

พัฒนาระบบ Backend และฐานข้อมูลสำหรับจัดเก็บข้อมูลผู้ใช้ ประวัติการเล่น คะแนน สถิติการเล่น และความคืบหน้าของแต่ละ Stage และ Biome เพื่อให้สามารถแสดงข้อมูลในหน้า Profile และระบบ Leaderboard ได้

## 11.7 ทดสอบและปรับปรุงระบบ

ทดสอบการทำงานของเว็บไซต์และระบบตรวจจับท่าทางในสภาพแวดล้อมการใช้งานจริง โดยตรวจสอบความถูกต้องของการควบคุมตัวละคร ความแม่นยำของการตรวจจับท่าทาง ความหน่วงของระบบ การทำงานของกลไกเกม ระบบ Biome และ Stage รวมถึงแก้ไขข้อผิดพลาดและปรับปรุงประสิทธิภาพของระบบ

## 11.8 ประเมินความพึงพอใจของผู้ใช้งาน

นำเว็บไซต์เกมที่พัฒนาเสร็จแล้วให้กลุ่มผู้ใช้งานทดลองเล่น และเก็บข้อมูลความคิดเห็นและความพึงพอใจเกี่ยวกับการใช้งาน ระบบควบคุม ความสนุก ความน่าสนใจ ระดับความยาก การออกแบบ UI/UX และความพึงพอใจโดยรวม เพื่อนำผลที่ได้มาวิเคราะห์และใช้ในการปรับปรุงระบบ

## 11.9 วิเคราะห์ผลและสรุปผลโครงการ

นำผลการทดสอบระบบ ความแม่นยำของการตรวจจับท่าทาง ความหน่วงของระบบ และผลการประเมินความพึงพอใจของผู้ใช้งานมาวิเคราะห์และสรุปผล เพื่อประเมินว่าระบบที่พัฒนาขึ้นสามารถทำงานได้ตามวัตถุประสงค์และขอบเขตของโครงงานหรือไม่

## 11.10 จัดทำเอกสารและรายงานผลโครงการ

จัดทำเอกสารรายงานฉบับสมบูรณ์ โดยรวบรวมรายละเอียดตั้งแต่การศึกษาปัญหา แนวคิดและทฤษฎีที่เกี่ยวข้อง การออกแบบระบบ ขั้นตอนการพัฒนา ผลการทดสอบ ผลการประเมิน และข้อเสนอแนะสำหรับการพัฒนาต่อยอดในอนาคต

# **1\. บทนำ**

## 1.1 ที่มาและความสำคัญของปัญหา

ปัจจุบันประชาชนชาวไทยจำนวนมากมีพฤติกรรมเนือยนิ่งและมีกิจกรรมทางกายไม่เพียงพอ ซึ่งเป็นปัจจัยเสี่ยงสำคัญต่อโรคไม่ติดต่อเรื้อรัง โดยการศึกษาของ Topothai et al. (2020) พบว่าระดับกิจกรรมทางกายของประชาชนชาวไทยยังต่ำกว่าระดับที่แนะนำเพื่อสุขภาพที่ดี สะท้อนให้เห็นถึงความจำเป็นในการพัฒนาแนวทางหรือเครื่องมือที่สามารถกระตุ้นให้ประชาชนเคลื่อนไหวร่างกายได้อย่างต่อเนื่อง งานวิจัยด้าน Active Video Games (AVGs) พบว่าการใช้การเคลื่อนไหวร่างกายเป็นกลไกควบคุมเกมสามารถเพิ่มอัตราการเต้นของหัวใจ การใช้ออกซิเจน และการเผาผลาญพลังงานได้ในระดับใกล้เคียงกับการออกกำลังกายรูปแบบทั่วไป (Peng, Lin, & Crouse, 2011\) นอกจากนี้ งานวิจัยด้าน Gamification ยังชี้ให้เห็นว่าองค์ประกอบของเกมสามารถช่วยเพิ่มแรงจูงใจและการมีส่วนร่วมของผู้ใช้ โดยเฉพาะในบริบทด้านสุขภาพ (Hamari et al., 2014; Johnson et al., 2016\)

โครงงานนี้จึงพัฒนาเว็บไซต์เกมออกกำลังกายที่ใช้การตรวจจับท่าทางร่างกาย (Pose Estimation) ผ่านกล้องเว็บแคม โดยให้ผู้เล่นขยับตัวไปทางซ้ายหรือขวาเพื่อควบคุมตัวละคร และวิ่งอยู่กับที่เพื่อให้ตัวละครยิงโจมตีศัตรู หากผู้เล่นหยุดเคลื่อนไหว ตัวละครจะหยุดยิงทันที เพื่อส่งเสริมให้เกิดการเคลื่อนไหวอย่างต่อเนื่อง โดยระบบตรวจจับท่าทางสามารถประมวลผลแบบเรียลไทม์บนคอมพิวเตอร์ทั่วไปโดยไม่ต้องใช้อุปกรณ์เฉพาะทาง โครงงานนี้มุ่งศึกษาว่าการออกแบบ Exergame ที่ใช้การเคลื่อนไหวร่างกายเป็นกลไกควบคุมโดยตรง ร่วมกับองค์ประกอบของเกม จะสามารถส่งเสริมกิจกรรมทางกายและแรงจูงใจภายในของผู้ใช้งานได้มากกว่าการเคลื่อนไหวรูปแบบเดียวกันที่ไม่มีองค์ประกอบของเกมหรือไม่

## 1.2 คำถามการวิจัย

•     องค์ประกอบของเกม ได้แก่ ระบบศัตรู ระบบคะแนน และระดับความยากที่ปรับเปลี่ยนได้ ส่งผลต่อแรงจูงใจภายในของผู้เล่นอย่างไร 

•     กลไกเกม เช่น ระบบศัตรู ระบบคะแนน และระดับความยากที่ปรับเปลี่ยนได้ ส่งผลต่อแรงจูงใจภายใน (Intrinsic Motivation) และความต่อเนื่องในการเล่น/ออกกำลังกายของผู้ใช้งานอย่างไร

# **2\. วัตถุประสงค์ของโครงงาน**

•     เพื่อพัฒนาเว็บไซต์เกมออกกำลังกาย (Exergame) ที่ใช้เทคโนโลยีตรวจจับท่าทางร่างกายผ่านกล้องเว็บแคม โดยให้การเคลื่อนไหวร่างกายของผู้เล่น (การก้าวซ้าย-ขวาเพื่อหลบ และการวิ่งอยู่กับที่เพื่อยิง) เป็นกลไกควบคุมเกมโดยตรง

•     เพื่อศึกษาผลของกลไกเกม เช่น ระบบศัตรู ระบบคะแนน และระดับความยาก ต่อความเข้มข้นของกิจกรรมทางกายและแรงจูงใจภายในของผู้เล่น

•     เพื่อประเมินความแม่นยำและความหน่วง (Latency) ของระบบตรวจจับการเคลื่อนไหวผ่านกล้องเว็บแคม ว่าเพียงพอต่อการใช้เป็นกลไกควบคุมเกมแบบเรียลไทม์หรือไม่

| ระบบคะแนน | • เพิ่มคะแนนตามเงื่อนไข เช่น ระยะเวลาในการเคลื่อนไหว จำนวนศัตรูที่กำจัด และการผ่านด่าน • แสดงคะแนนปัจจุบันระหว่างเล่นเกม • บันทึกคะแนนเมื่อจบเกมหรือจบด่าน • ป้องกันการบันทึกคะแนนซ้ำจากผลการเล่นครั้งเดียวกัน |  |
| ระบบ Biome และ Stage | • ระบบรองรับการแบ่งเกมออกเป็นหลาย Biome • ต้นแบบประกอบด้วยอย่างน้อย 2 Biome ได้แก่ Forest Biome และ Desert Biome • แต่ละ Biome ประกอบด้วย 10 Stages • ผู้เล่นต้องผ่านแต่ละ Stage ตามลำดับเพื่อปลดล็อก Stage และ Biome ถัดไป • แต่ละ Biome สามารถมีฉาก รูปแบบศัตรู และระดับความยากแตกต่างกัน • ระบบแสดง Stage ที่ผ่านแล้ว Stage ปัจจุบัน และ Stage ที่ยังไม่ปลดล็อก |  |
| หน้าสรุปผลหลังเล่น | • แสดงคะแนน จำนวนศัตรูที่กำจัด ระยะเวลาเล่น และจำนวนการเคลื่อนไหวที่ระบบตรวจพบ • แสดง Stage และ Biome ที่ผู้เล่นผ่าน • แสดงผลเปรียบเทียบกับประวัติการเล่นของผู้เล่นเอง • ผู้เล่นสามารถเลือกเล่นอีกครั้ง กลับหน้าเลือกด่าน หรือกลับหน้าแรกได้ |  |
| หน้าโปรไฟล์ผู้เล่น | • แสดงข้อมูลส่วนตัวของผู้เล่น • แสดงประวัติการเล่น คะแนนสูงสุด ระยะเวลาเล่นสะสม และจำนวนการเคลื่อนไหวสะสม • แสดงความคืบหน้าของแต่ละ Biome และ Stage • แสดงผลเปรียบเทียบกับสถิติของผู้เล่นเองในอดีต |  |
| ระบบตารางคะแนน | • แสดงลำดับคะแนนสูงสุดของผู้เล่น • แสดงชื่อที่ใช้ในเกม คะแนน และวันที่บันทึกคะแนน • ผู้เล่นสามารถเลือกไม่แสดงชื่อจริงและใช้ชื่อที่ตั้งภายในเกมได้ |  |
| ระบบจัดเก็บข้อมูล | • จัดเก็บข้อมูลสมาชิก ประวัติการเล่น คะแนน สถิติการเคลื่อนไหว และความคืบหน้าของด่าน • ตรวจสอบสิทธิ์ก่อนเข้าถึงหรือแก้ไขข้อมูล • ไม่จัดเก็บภาพ วิดีโอ หรือข้อมูลตำแหน่งข้อต่อจากกล้องแบบรายเฟรม • จัดเก็บเฉพาะค่าผลลัพธ์ที่จำเป็นต่อการสรุปผลและการประเมิน |  |
| การประเมินประสิทธิภาพทางเทคนิค | • ทดสอบความถูกต้องของการตรวจจับการก้าวหรือเอียงตัวซ้าย-ขวา การวิ่งอยู่กับที่ และการหยุดนิ่ง • วัดความหน่วงตั้งแต่ระบบรับภาพจนถึงการตอบสนองของตัวละคร • บันทึกอัตราเฟรมและสภาพแวดล้อมของอุปกรณ์ที่ใช้ทดสอบ • รายงานค่าเฉลี่ย ค่าการกระจาย และข้อจำกัดที่พบจากการทดสอบ |  |
| การประเมินแรงจูงใจและการใช้งาน | • แบ่งผู้เข้าร่วมเป็นกลุ่มทดลองและกลุ่มควบคุม • กลุ่มทดลองใช้ระบบเกมฉบับสมบูรณ์ที่มีตัวละคร ศัตรู คะแนน และระดับความยาก • กลุ่มควบคุมทำกิจกรรมการเคลื่อนไหวรูปแบบเดียวกันผ่านระบบตรวจจับท่าทาง แต่ไม่มีตัวละคร ศัตรู คะแนน หรือองค์ประกอบเกม • ประเมินแรงจูงใจภายในด้วยแบบสอบถาม Intrinsic Motivation Inventory (IMI) • เปรียบเทียบคะแนน IMI จำนวนการเคลื่อนไหว และระยะเวลาที่เคลื่อนไหวอย่างต่อเนื่องระหว่างสองกลุ่ม • วิเคราะห์ผลด้วย Independent Samples t-test หรือสถิติอื่นที่เหมาะสมกับลักษณะข้อมูล |  |
| การจัดการข้อมูลผู้เข้าร่วมทดลอง | • ชี้แจงรายละเอียดและขอความยินยอมก่อนเก็บข้อมูล • ไม่บันทึกภาพหรือวิดีโอจากกล้องระหว่างการทดลอง • ใช้รหัสผู้เข้าร่วมแทนชื่อในการวิเคราะห์ผล • จำกัดการเข้าถึงข้อมูลผลการทดลองเฉพาะผู้จัดทำและผู้เกี่ยวข้อง |  |
| แพลตฟอร์มที่รองรับ | • พัฒนาในรูปแบบ Web Application • รองรับคอมพิวเตอร์เดสก์ท็อปและแล็ปท็อปที่มีกล้องเว็บแคม • ใช้งานผ่านเว็บเบราว์เซอร์รุ่นปัจจุบันที่รองรับการเข้าถึงกล้องและการประมวลผลกราฟิก • ต้องเชื่อมต่ออินเทอร์เน็ตสำหรับระบบสมาชิก การบันทึกผล และตารางคะแนน |  |
| ข้อจำกัดของระบบ | • ความแม่นยำขึ้นอยู่กับแสงสว่าง ตำแหน่งกล้อง ระยะห่าง เสื้อผ้า และประสิทธิภาพของอุปกรณ์ • รองรับการตรวจจับบุคคลครั้งละ 1 คน • ระบบไม่ใช่อุปกรณ์ทางการแพทย์และไม่ใช้สำหรับวินิจฉัยโรค • จำนวนการเคลื่อนไหวเป็นค่าที่ตรวจวัดโดยระบบ ไม่ใช่ค่าพลังงานหรือแคลอรีที่ได้รับการรับรองทางการแพทย์ |  |

# **6\. ผลที่คาดว่าจะได้รับ**

6.1 ได้ต้นแบบเว็บไซต์เกมออกกำลังกายที่ใช้กล้องเว็บแคมและการตรวจจับท่าทางร่างกายเป็นกลไกควบคุมเกมโดยตรง

6.2 ได้ระบบเกมที่ประกอบด้วยตัวละคร ศัตรูและบอส คะแนน แถบพลังชีวิต ระดับความยาก Biome Stage ประวัติการเล่น และตารางคะแนน

6.3 ได้ผลการประเมินความแม่นยำ ความหน่วง และข้อจำกัดของระบบตรวจจับท่าทางในการควบคุมเกมแบบเรียลไทม์

6.4 ได้ข้อมูลเกี่ยวกับผลขององค์ประกอบเกมต่อแรงจูงใจภายใน ปริมาณการเคลื่อนไหว และความต่อเนื่องในการทำกิจกรรมทางกายของผู้ใช้งาน

6.5 ได้แนวทางสำหรับการพัฒนาเกมออกกำลังกายบนเว็บเบราว์เซอร์ที่ไม่จำเป็นต้องใช้อุปกรณ์ตรวจจับการเคลื่อนไหวเฉพาะทาง

6.6 ผู้ที่สนใจสามารถนำผลการพัฒนาและผลการประเมินไปใช้เป็นพื้นฐานในการศึกษา วิจัย หรือพัฒนาระบบ Exergame เพิ่มเติมในอนาคตได้
